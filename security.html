Sécurité du site

Ce qui est appliqué

  • Site 100 % statique : aucun compte, aucune authentification, aucune base de données, aucune API, aucun formulaire.
  • JavaScript minimal, sans dépendance ni script tiers (aucun tracker, aucun CDN).
  • Aucune injection HTML dynamique côté client : tout le contenu est généré en HTML statique.
  • Headers de sécurité configurables selon l'hébergeur (fichiers _headers et .htaccess fournis) : Content-Security-Policy restrictive, X-Content-Type-Options: nosniff, Referrer-Policy: strict-origin-when-cross-origin, Permissions-Policy restrictive.
  • Aucune donnée personnelle sensible publiée (téléphone et adresse non publiés ; captures à anonymiser avant ajout).
  • Liens externes en rel="noopener noreferrer".

Limites et risques résiduels (honnêteté)

  • Aucun site n'est « sécurisé à 100 % » : ce portfolio réduit la surface d'attaque, il ne l'élimine pas.
  • L'hébergeur peut ne pas appliquer tous les headers (ex. GitHub Pages ne permet pas de personnaliser les headers).
  • L'adresse e-mail publiée peut être captée par des robots (spam) — c'est un choix assumé pour être contactable.
  • Le principal risque reste humain : publier par mégarde une capture non anonymisée. La checklist avant publication (fichier CHECKLIST-PUBLICATION.md) sert de garde-fou.
